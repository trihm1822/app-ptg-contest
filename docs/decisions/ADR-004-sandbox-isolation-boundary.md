# ADR-004: Sandbox Execution Boundary & Compiler Resource Protection

* **Status:** Accepted  
* **Date:** 2026-10-23  
* **Deciders:** Principal Architect, Core Developer  
* **Context:** MVP-0 (Phase 0)  

## Context and Problem Statement
PTG compiles and executes arbitrary, untrusted C++17 source code generated by an LLM or provided by a user. Untrusted code poses severe security and operational risks:
1. **Runtime Escapes:** Malicious code attempting to read sensitive host files (`/etc/shadow`, `.env`), spawn fork bombs, or open network sockets.
2. **Compiler Denial of Service (Compiler Bomb):** Malicious preprocessor directives (e.g., `#include </dev/urandom>`), recursive template expansions, or gigantic macros that consume 100% host CPU and exhaust RAM during `g++` compilation.
3. **Execution Resource Exhaustion:** Infinite loops or unbounded dynamic memory allocations during testcase execution.

## Decision
1. **Layered Docker Sandbox Architecture:**
   - Execute both compilation and execution inside a disposable, isolated Docker container based on a minimal, hardened image (e.g., `gcc:13-bookworm` or Debian slim).
   - The container MUST be destroyed immediately after execution (`--rm`).
2. **Mandatory Runtime Restrictions (Execution Flags):**
   - `--network=none`: Total network isolation.
   - `--read-only`: Read-only root filesystem. Only a dedicated per-job workspace is mounted read-write.
   - `--user=nobody`: Never run as root.
   - `--cap-drop=ALL`: Drop all Linux kernel capabilities.
   - `--security-opt=no-new-privileges`: Prevent privilege escalation.
   - `--cpus="1.0"`: Strict 1-core CPU allocation.
   - `--memory="256m"` and `--memory-swap="256m"`: Hard memory limit with swap disabled.
   - `--pids-limit=32`: Strict process limit preventing fork bombs.
3. **Dedicated Compilation Resource Protections:**
   - The compilation step MUST be bounded by hard OS-level limits:
     ```bash
     timeout -s KILL 10s g++ -O2 -std=c++17 -fbracket-depth=256 -fmax-errors=3 -o solution solution.cpp
     ```
   - Max compiler memory: 512 MB.
   - Max compilation time: 10 seconds. Exceeding this marks the run as `COMPILE_FAILED` with error category `COMPILER_TIMEOUT`.
4. **Execution Time Limits:**
   - Default wall-clock execution timeout per testcase: 5 seconds.
   - Max output capture: 10 MB (prevents disk-filling attacks via endless `std::cout`).

## Consequences
### Positive
- Robust defense-in-depth: Protects the host operating system from malicious system calls, network leakage, and fork bombs.
- Complete compiler protection: Eliminates compiler-based resource exhaustion attacks.
- Clean state: Disposable containers guarantee no state or artifacts leak between test runs.

### Negative / Trade-offs
- Docker startup overhead: Spawning containers for each run introduces 200–400ms latency per invocation.
- Platform specificity: cgroups limits and seccomp profiles require Linux kernel support; developers on Windows must test against WSL2 or a dedicated Linux environment.
