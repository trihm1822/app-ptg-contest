# ADR-005: Reproducibility Metadata Record & Export Manifest Schema

* **Status:** Accepted  
* **Date:** 2026-10-23  
* **Deciders:** Principal Architect, Core Developer  
* **Context:** MVP-0 (Phase 0)  

## Context and Problem Statement
A core value proposition of PTG is **scientific reproducibility**: any exported testcase package must allow independent verification and identical recreation of test inputs and outputs in a pinned environment. Without strict metadata tracking, differences in compiler versions, random seeds, or generator source changes make it impossible to audit testcase provenance.

## Decision
1. **Cryptographic Artifact Hashing:**
   - Every input file (`.inp`), output file (`.out`), source code file (`brute.cpp`, `optimized.cpp`, `generator.cpp`, `validator.cpp`), and problem specification MUST have its SHA-256 hash computed and recorded.
2. **Deterministic Manifest (`manifest.json`):**
   - Every exported package (`PTG-EXPORT.zip`) MUST contain a root `manifest.json` complying with the following schema:
   ```json
   {
     "manifest_version": "1.0",
     "created_at": "2026-10-23T10:00:00Z",
     "problem_id": "two-sum",
     "problem_revision_hash": "sha256:abcdef...",
     "status": "APPROVED_FOR_EXPORT",
     "verification_status": "PASSED_CHECKS",
     "toolchain": {
       "ptg_version": "0.1.0",
       "compiler": "g++ (Debian 13.2.0-25) 13.2.0",
       "compiler_flags": ["-O2", "-std=c++17"],
       "runner_image": "gcc:13-bookworm@sha256:123456..."
     },
     "llm_metadata": {
       "provider": "gemini",
       "model": "gemini-2.5-flash",
       "prompt_template_version": "1.0",
       "prompt_hash": "sha256:789abc...",
       "total_tokens": 3450,
       "estimated_cost_usd": 0.0012
     },
     "generator": {
       "source_hash": "sha256:def123...",
       "global_seed": 424242,
       "test_count": 20
     },
     "artifacts": [
       {
         "file": "tests/test01.inp",
         "sha256": "sha256:a1b2c3...",
         "seed": 4242421,
         "subtask_id": 1,
         "size_bytes": 104
       },
       {
         "file": "tests/test01.out",
         "sha256": "sha256:d4e5f6...",
         "execution_time_ms": 12,
         "memory_kb": 3400
       }
     ]
   }
   ```
3. **Redaction of Secrets:**
   - The manifest and local run record MUST NEVER contain API keys, authorization tokens, or sensitive host paths.

## Consequences
### Positive
- Full auditability: Anyone inspecting the exported ZIP can verify that test outputs were generated by the recorded binaries on the recorded inputs.
- Academic and competitive standard: Satisfies the stringent criteria of competitive programming platforms and academic problem setting.
- Clean debugging: If an input is reported invalid, the exact seed and subtask can be isolated instantly.

### Negative / Trade-offs
- File size overhead: Storing per-test hashes and execution metrics adds several kilobytes to the ZIP package.
- Precision limits: Reproduction of LLM-generated code cannot be guaranteed across provider updates; the manifest clearly separates LLM generation metadata from deterministic C++ test generation metadata.
